# snapgene-primer-registrar（日本語）

*[English README](README.md)*

Excel(オリゴ管理表)の配列と SnapGene の `.dna` プラスミドファイルを突き合わせ、
配列が**完全一致**するオリゴだけをそのプラスミドの「プライマー」として自動登録するツールです。

新しいオリゴを表に追加するたびに繰り返し実行することを想定しており、
既に登録済みのプライマーは再登録せず自動的にスキップします（冪等）。

## できること

- 指定フォルダ内のすべての `.dna` ファイルを走査
- Excel の `Oligo` シートに列挙された各オリゴ配列について、フォワード鎖・リバースコンプリメント鎖の両方向、環状プラスミドの起点をまたぐ結合部位も含めて**完全一致**する箇所を検索
- 一致した場合のみ、SnapGene がプライマーを追加したときと同じ形式の `<Primer>` エントリを `.dna` ファイルに書き込み
- プライマー名は `Name` 列と ID から `Name (ID)` の形で組み立て（Excel の `Concat.` 列（`=Name & " (" & ID & ")"`）と同じ文字列になるため、`Concat.` 列が未入力でも表と一致）
- そのファイルに同じオリゴID（例: `O01-01`）を含むプライマーが既に存在する場合はスキップ
- 既定は**ドライラン**。ファイルを書き換えず、レポートのみを出力。`--apply` を付けたときだけ書き込み
- 書き込み前に自動バックアップ、書き込み後は実際にディスクへ書かれた内容を読み直して位置と配列を再検証（後述）

## インストール

```powershell
pip install -r requirements.txt
```

## 読み込む Excel の形式

本ツールは Excel を読み取るだけで、書き換えません。列の指定方法は列によって
異なります。そのため、次の形式が必要です。

| 場所 | 入れる内容 | 例 |
| --- | --- | --- |
| 1 行目 | ヘッダー行 | |
| A 列 | オリゴ ID。この列の見出しは列名ではなく区分の見出し（`Oligo`）なので、**位置で指定**します。 | `O01-01` |
| `Name` 列 | オリゴの名称 | `Example_Del.F` |
| `Sequence` 列 | 配列。A/C/G/T のみ、大文字小文字は区別しません。 | `ACGTACGT…` |

これ以外の列は無視します。`Name` 列と `Sequence` 列の位置と順序は任意です。

次の行は読み飛ばします。ID・名称・配列のいずれかが空の行と、A・C・G・T 以外の
文字を含む配列の行です。後者には縮重塩基と修飾を含む配列が該当します。読み飛ばし
たことは画面に表示されません。

次の場合はエラーで停止します。`--sheet` で指定したシートが存在しない場合と、
`Name` 列または `Sequence` 列が見つからない場合です。

## 使い方

Excel を **Excel アプリで開いたままにしない**でください（ファイルロックで読み込みに失敗します）。

```powershell
# まずはドライラン（何も書き換えず、レポートだけ出力）
python register_primers.py --excel "path\to\Nucleotide.List.xlsx" --plasmid-dir "path\to\PlasmidList"

# レポート内容を確認して問題なければ --apply を付けて実行
python register_primers.py --excel "path\to\Nucleotide.List.xlsx" --plasmid-dir "path\to\PlasmidList" --apply
```

`--excel` の既定値は `./InSilico/Nucleotide.List.xlsx` です。`--plasmid-dir` の既定値は
`./InSilico/Vector/PlasmidList` です。このレイアウトのプロジェクトルートで実行する場合は、
どちらの引数も省略できます。

```powershell
python register_primers.py            # ドライラン
python register_primers.py --apply    # 実際に登録
```

新しいオリゴを追加したときは、この2行目のコマンドをそのまま再実行してください。
過去に登録済みのものは自動的にスキップされ、新規分だけが追加されます。

フォルダ全体ではなく、特定のファイルだけに登録することもできます。`--plasmid-dir` の
外にある参照用のプラスミドが該当します。この場合は `--plasmid-dir` を指定せず、
`--file` を 1 ファイルにつき 1 回指定します。

```powershell
python register_primers.py --file "path\to\LocusA.dna" --file "path\to\LocusB.dna" --apply
```

### 主なオプション

| オプション | 説明 | 既定値 |
| --- | --- | --- |
| `--excel` | Nucleotide List のブック（`Oligo` シートを読む） | `./InSilico/Nucleotide.List.xlsx` |
| `--sheet` | シート名 | `Oligo` |
| `--plasmid-dir` | `.dna` を再帰的に探索するフォルダ | `./InSilico/Vector/PlasmidList` |
| `--file` | `--plasmid-dir` の探索の代わりに、指定した特定の `.dna` ファイルにのみ登録する。複数回指定可 | (なし) |
| `--apply` | 実際にファイルを書き換える（省略時はドライラン） | 無効 |
| `--backup-dir` | 書き換え前のバックアップ先 | `<plasmid-dir>`（または最初の `--file` の親フォルダ）の兄弟ディレクトリ `_primer_registration_backups/<実行時刻>` |
| `--report` | CSV レポートの出力先 | `./primer_registration_report_<実行時刻>.csv` |

## 安全設計

実験で使用中の `.dna` ファイルを直接書き換えるツールなので、以下を徹底しています。

1. **ドライランを既定とします**: `--apply` を付けない限り、ファイルは変更されません。
2. **自動バックアップ**: 書き換えるファイルごとに、書き込み直前のバイト列をそのまま `--backup-dir` にコピーします。
3. **原子的な書き込み**: 一時ファイルに書いてから `os.replace()` で置き換えるため、書き込み中の異常終了で元ファイルが壊れることはありません。
4. **位置の二重検証**:
   - 登録前: 計算した結合位置（0-based, プラスミド配列に対する開始・終了塩基番号）から実際に塩基を再抽出し、登録しようとしているオリゴ配列（または環の反対鎖に結合する場合はその逆相補鎖）と完全に一致するかを確認してから初めて書き込みを行います。一致しなければ例外を送出しその項目の登録を中止します。
   - 登録後: 実際にディスクへ書き込まれたファイルを読み直し、追加したプライマーの名前・配列・結合位置をもう一度独立に再検証します。ここで不一致が検出された場合は直前に取ったバックアップへ即座に復元します。
   - この設計により、「数式的に計算した塩基位置」と「実際のプラスミド配列上のその位置の塩基」が常に一致していることを機械的に保証しています。
5. **CSV レポート**: 実行のたびに「どのオリゴをどのファイルのどの位置に登録したか / 既に登録済みでスキップしたか」を CSV に出力し、追跡できるようにしています。

## `.dna` ファイルフォーマットについて

SnapGene の `.dna` は「1バイトのブロック種別 + 4バイト(ビッグエンディアン)の長さ + 中身」を並べたバイナリコンテナです。
本ツールは、SnapGene 自身が既存の `.dna` ファイルに書き込んだプライマー 713 件から座標系を逆算・検証しました。
座標の規約を確定させた事例は、合成データとして `tests/test_matching.py` に再現しています。

- プライマーの結合位置は `BindingSite location="start-end"` で、**0-based・両端を含む**座標です。
- `boundStrand="0"` はプライマー配列がプラスミドの＋鎖にそのまま現れる場合（＝マイナス鎖に結合）。
- `boundStrand="1"` はプライマー配列がプラスミドの＋鎖の逆相補配列として現れる場合（＝プラス鎖に結合）。
- 環状プラスミドで起点をまたぐ結合部位は `end < start` という形（例: `"2808-49"`）で表現されます。

新規プライマーの追加は、既存の `Primers` ブロックの XML テキストを文字列として
操作して行います。`<Primer>...</Primer>` 要素を追記し、`nextValidID` を更新する
だけの処理です。既存のプライマーエントリのバイト列は変更しません。そのため、
既存データが壊れる可能性を抑えられます。実装は `snapgene_primers/primers_xml.py`
にあります。

## 制限事項

- 完全一致（大文字小文字を無視した100%一致）のみを対象とし、ミスマッチを許容した部分一致プライマーの登録は行いません。
- 同一オリゴが同一プラスミド内の複数箇所に完全一致する場合は、見つかった結合部位をすべて1つの `<Primer>` エントリの複数 `BindingSite` として登録します。
- 表示用の Tm（融解温度）は簡易な近似式（Wallace則 / GC%式）であり、SnapGene 内部の計算値と厳密には一致しません。判定ロジックには使用していません。
- Excel 側の `Oligo` シート自体は読み取り専用で扱い、書き換えません。

## フォーマットは公開されていません

`.dna` は仕様が公開されていない独自形式です。本ツールが扱う形式の情報は、
SnapGene が書き込んだファイルを読んで逆算したものです。したがって、次の 2 点を
前提とします。

- **SnapGene の更新で動作しなくなる場合があります。** 形式が変わった場合、
  SnapGene が正しく読めないファイル、または開けないファイルを書き込む可能性が
  あります。この場合の復旧手段は、書き込み前のバックアップだけです。バックアップは
  SnapGene で開いて確認するまで保持します。
- **開発元の承認は受けていません。** SnapGene は Dotmatics の製品です。
  「SnapGene」は同社の商標です。本ツールは同社とは無関係です。承認も支援も
  受けていません。名称は、読み込む対象を示す目的で使用しています。

新しい版の SnapGene で初めて使用するときは、書き込んだファイルを SnapGene で
開いて確認します。実行後は CSV レポートを確認します。
